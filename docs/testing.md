# 测试与验收说明

这套工具主要通过 Vibe Coding 完成，功能调整比较频繁。页面能正常打开只是第一步，每次改动后还要确认车辆、任务、邮件和 Sales 数据之间的关系没有被破坏。

## 目前怎么验证

自动测试脚本现有 96 项断言，最近一次本地运行已通过。检查内容主要包括：

- 任务：今日任务、逾期待办、搜索和周期任务；
- 车辆：VIN 格式、重复车辆、办理项目和旧数据迁移；
- 邮件：CSV 解析、重复记录、多车辆关联以及与 Sales 的信息对比；
- 报表：XLSX 读取、规则生成、异常识别和待做合同提取；
- 数据联动：车辆状态、邮寄记录和退保任务是否同步。

报表检查会覆盖公式、日期、数值、格式和缺失列等问题。测试使用固定的虚构样例，便于每次调整后重复验证。

## 来自实际使用的两个案例

### 公式被固定数字覆盖

某个原本应该保留公式的单元格被粘贴成普通数字。当前数值看起来正常，但以后更新时不会继续计算。测试样例会检查公式是否仍然存在，也会检查公式结果是否异常。

### 粘贴后格式错位

从其他表格粘贴数据后，部分单元格的格式和所在列不一致。测试样例保留了这类情况，用来确认工具仍能指出具体位置。

这两个案例来自试运行中发现的问题，后续修改报表检查功能时会继续回测。

## 关键验收场景

| 场景 | 验收要求 |
|---|---|
| 周期任务 | 完成后只生成一次下一周期任务；反复切换原任务状态不能继续复制 |
| 邮件与 Sales 冲突 | 车牌、价格或经销商不一致时，显示冲突原因并交由人工确认 |
| 一封邮件包含多辆车 | 为每辆车建立独立索引，并指向同一封原始邮件；重新扫描不重复创建 |
| 报表只读检查 | 显示异常单元格和判断原因，不修改用户上传的工作簿 |

## 测试还没有覆盖什么

96 项断言只能防止已知功能在修改后失效。目前还需要继续验证：

- 更大规模的车辆和邮件数据；
- 来自不同人员的 Excel 文件和邮件写法；
- VIN 后 5 位重复时的实际操作体验；
- 不同 Windows 和经典 Outlook 环境；
- 长期使用后的本地容量、备份和恢复。

自动测试用于检查功能有没有被改坏，试运行数据用于判断工具是否真的有用，两类结果分别记录。
