# JOYone 产品说明

更新：2026-09-12

## 产品定位

面向二手车运营人员的业务工作台，以表格核查为首个完整流程。辅助发现问题、整理材料、生成草稿并追踪任务，业务人员负责判断和最终提交。

## 核心流程

选择任务 → 导入原表与新增资料 → 比较差异 → 查看问题及来源 → 人工确认或退回 → 下载报告或工作副本 → 记录处理结果。

需要补充资料的问题可创建跟进，记录负责人、期限、反馈材料及复核决定。不能把收到材料等同于完成复核。

## 当前界面

- **今日工作**：待处理、处理中、待确认、已完成及问题跟进。
- **表格核查**：差异、缺项、公式问题、格式建议和不确定匹配。
- **车辆任务**：流程节点、材料、时间和备注。
- **邮件草稿**：模板、字段核对、复制及打开草稿。
- **搜索与记录**：查询表格、车辆、邮件草稿及核查历史。
- **询问 JOYone**：右上角的唯一 Agent 对话入口；同一窗口可切换本地工作查询。Agent 对话目前使用预设示例回复。
- **接入中心**：左侧的能力管理入口，演示链接、内嵌、API、Tool / MCP。

## 接入方案

Agent 优先使用已有聊天服务的固定入口，真实目标地址由受保护的服务端配置，不在公开静态页面中展示。若内嵌受限，则使用独立页面。GitHub Pages 只演示这个过程。

API 演示采用服务目录 → 模拟申请 → 文档预览/导出 → 调用测试。导出的 OpenAPI 3.0 JSON 是虚构示例，不可当作公司接口文档。文档导出本身也不授予调用权限。

Tool 和 MCP 分别展示连接与工具调用流程。普通网页 URL 不能替代协议连接。当前静态示例不运行协议客户端或后台代理。

## 人工控制规则

1. 不自动更新正式系统，不自动发送邮件。
2. 表格原件保留；仅已接受的可应用差异进入工作副本。
3. 多个 VIN 候选不自动选定，需人工核查。
4. 输出标记来源、问题、建议与人工决定。
5. 未完成的核查项不能被视为整批审核完成。
6. 模拟对话不读取工作查询中的资料；两种状态明确区分。
7. 不把模拟授权、模拟成功结果描述为真实连接。

## 验收

| 场景 | 要求 |
|---|---|
| 首次打开 | 可用虚构示例开始，不需要接口密钥 |
| 表格核查 | 差异可定位，人工决定可记录，原件保留 |
| 查询冲突 | 重复 VIN、缺失字段和公式问题不会被静默忽略 |
| Agent 对话 | 位于“询问 JOYone”内，左侧无重复对话入口 |
| 四种接入 | 各有可操作界面，能看到成功与异常状态 |
| API 文档 | 可查看和导出有效示例 JSON，申请状态与调用结果分开 |
| 手机 | 主要控件和对话可操作，页面无横向溢出 |

## 后续验证

在获批环境确认接口认证、文件输出质量、访问控制、任务持久化及调用日志。先完成 Excel 小范围试点，再评估邮件、OCR 和其他系统接入。记录实际用时、发现问题准确率、不确定项比例、输出可用率及回退次数，依据真实结果决定扩展范围。
